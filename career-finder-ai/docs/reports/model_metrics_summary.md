## Best Rubric-Assisted Model (Track B — leakage demo)

These models use rubric component scores (`major_fit_score`, `skill_match_score`, …) as features. Because `target_score` is a weighted sum of those same components, the metrics are **unrealistically strong** and must NOT be presented as honest model performance.

- **Model:** `rubric_assisted_ridge`
- **MAE:** 0.0229
- **RMSE:** 0.0281
- **R²:** 1.0000
- **Precision@5:** 0.2400
- **Feature set:** `text_and_rubric_components`
- **Leakage-safe:** `False`

## Why Rubric-Assisted Is Not the Honest Model

The `target_score` label is defined as a weighted linear combination of eight rubric component scores (`major_fit_score`, `skill_match_score`, `role_interest_score`, `city_match_score`, `program_type_score`, `work_mode_score`, `verification_score`, `interview_score`). When those same eight values are included as model features, any regressor can reconstruct `target_score` almost perfectly by learning the linear weights — resulting in near-zero MAE and R² ≈ 1.0. This is **target leakage**, not genuine generalisation.

The fair models (Track A) exclude all rubric components and must predict `target_score` from raw student profile text and opportunity metadata alone. Their lower R² reflects honest uncertainty, not poor engineering.
